# v1.1.0 — Explicit Reconstruction and Forecasting Modes

Released: 2026-09-23

PySHRED v1.1.0 adds an explicit `mode` option to `DataManager` and `ParametricDataManager`, selecting how each sensor sequence is aligned to the full-state timestep it maps to.

## What changed

`mode` accepts two values:

| mode | sensor sequence for target `u(t)` |
| --- | --- |
| `"reconstruct"` (default) | `s(t-lags+1) ... s(t)` |
| `"forecast"` | `s(t-lags) ... s(t-1)` |

`"reconstruct"` is the task the SHRED papers focus on: the full state is recovered from sensor measurements up to and including the current timestep. `"forecast"` predicts one step beyond the most recent measurement.

This is independent of the SHRED model's `latent_forecaster`, which performs multi-step forecasting in the latent space.

## Breaking change

Releases before v1.1.0 always built sequences the way `mode="forecast"` now does, with no way to select the reconstruction alignment. **The default is now `"reconstruct"`, so results will change for existing code that does not pass `mode`.**

To keep pre-v1.1.0 behavior, explicitly set `mode="forecast"`:

```python
manager = DataManager(mode="forecast")
```

Calling `prepare()` without having passed `mode` emits a one-time `UserWarning` describing the new default.

## Also in this release

- `lags` is now validated: a non-positive value raises `ValueError` instead of failing later inside NumPy.
- An invalid `mode` raises `ValueError` when the data manager is constructed, rather than at `prepare()` time.
